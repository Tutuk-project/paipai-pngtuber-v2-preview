# Vio Studio v2.0 — Checkpoint 59: PRISM iOS WebView URL Compatibility

Date: 2026-11-21
Repository: `Tutuk-project/paipai-pngtuber-v2-preview`
Branch: `main`
Scope: Solo OBS generated-link serialization for iOS WebView compatibility.

## Incident evidence
- Android loads the generated Solo OBS source.
- Safari on iOS loads the same overlay page and obtains microphone access.
- PRISM Live Studio on iOS fails when the generated Copy Link OBS URL is used.
- The generator encoded room credentials only in the URL fragment (`#room=...&token=...`). The overlay reader already supported both fragment and query parameters, but the generator did not produce a query-based compatibility URL.
- PRISM's official mobile documentation confirms that Web Page sources are supported on iOS and Android. The specific URL-fragment handling failure is a working compatibility hypothesis, not yet independently reproduced inside the PRISM iOS runtime.

## Source changes
- Solo OBS URL generation now writes `room` and `token` as query parameters, while preserving width/height parameters for Collaboration output.
- Overlay bootstrap prefers query credentials and retains fragment parsing for previously generated links.
- Immediately after credentials are read, the overlay removes `room` and `token` from the visible URL/history using `history.replaceState`; non-secret parameters such as dimensions and debug mode are retained.
- The overlay module cache-bust was updated to `20261121-prism-ios-query-1`.
- A regression test checks query-based generation, legacy fragment fallback, credential cleanup, and cache-bust.

## Security note
- Query credentials are included in the initial HTTPS page request, unlike fragment credentials. Removing them with `history.replaceState` prevents them from remaining in the visible URL/history and subsequent page navigation, but does not undo their inclusion in the initial request.
- Treat overlay links as bearer credentials. The token exposed during the incident must be rotated by generating a fresh OBS link; do not reuse the exposed link.
