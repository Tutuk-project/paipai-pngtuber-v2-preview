## Instrumentation implemented

### OBS overlay HUD

Open the existing shared overlay URL with `?debug=1` before its URL fragment, e.g. `overlay.html?debug=1#room=…&token=…`. The room/token values are placeholders; preserve the actual existing fragment exactly.

The on-screen HUD reports:

- Debug build ID and loaded module cache tag.
- Realtime status (`SUBSCRIBED`, `CHANNEL_ERROR`, `TIMED_OUT`, `CLOSED`) and last reported error.
- Last `player-layout` broadcast timestamp, member ID, seq, X/Y/scale, and whether it was applied or rejected (unknown member / stale seq).
- Last `overlay_poll` or `overlay_connect` request time, HTTP status, error, duration, per-member overrides and `updated_at`.
- Per-member effective transform passed to `AvatarRenderer.setRoomLayout()`, plus last applied layout sequence.
- rAF ticks per second and whether the animation loop is currently alive.
- localStorage/sessionStorage availability, anonymous/existing auth session status, and observed `TOKEN_REFRESHED` success.

### Creator console diagnostics

Each layout DB persistence logs `[CollabLayout] DB write result` with the member ID, X/Y/scale, returned override row and `updated_at`, or logs the error.

Each layout broadcast logs `[CollabLayout] broadcast result` with send status, member ID, sequence, X/Y/scale and elapsed time, or logs the error.

Reset-layout now uses the same instrumented persistence path.

### Edge Function response diagnostics

`set_room_override` now performs the upsert with `.select("room_id,user_id,overrides,updated_at").single()` and returns the persisted row to Creator. The overlay poll/snapshot responses now include the override `updated_at` timestamp.

## Code inspection: ranked boundary hypotheses

1. **Creator sequence reset remains a strong candidate, not yet fixed.** `src/app.js` initializes `layoutSequence = 0` in page memory and increments it for each layout broadcast. `src/overlay.js` retains a per-member `layoutSequences` map and rejects any received seq less than or equal to that member's previous seq. Reloading Creator can therefore restart at 1 while an already-open OBS page still remembers a higher sequence. The real test must capture this in the HUD before changing sequence behavior.
2. **Identity mismatch is not apparent in the inspected code.** Creator sends `currentUser.id`; the Edge Function's room-member and overlay snapshot rows use `vio_app_users.id` as `user_id`. OBS matches that same `member.user_id`. Confirm actual values in the runtime HUD/logs.
3. **Silent RLS no-op is less likely on this path.** The Edge Function uses the server secret key and now returns the selected upsert row. A missing row/error will be visible in Creator logs.
4. **Overlay Realtime policy appears to include overlay devices.** Runtime auth/session and actual channel status remain unverified.
5. **Snapshot/poll path is now observable.** Poll responses expose per-member `updated_at`; HUD will show HTTP errors and stale values.
6. **rAF/render application remains observable.** The HUD records render ticks and the transform passed into the renderer. No render-path behavior was changed.
7. **Cache mismatch is observable** through the module cache tag and HUD build ID.
8. **Coordinate normalization remains to be validated** against the actual Creator and OBS canvas sizes.
