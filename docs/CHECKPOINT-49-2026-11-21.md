# Vio Studio v2.0 — Checkpoint 49
Date: 2026-11-21

## User test findings
1. Solo OBS improved after the previous renderer changes, but still has delayed mic response and occasional frame stalls.
2. Imported overlay links in streaming apps showed `Realtime channel error: CHANNEL_ERROR`; the local mic did not respond, although avatar animation and visual effects rendered.
3. Collaboration grid was visible but too thin.
4. Collaboration preview still appeared portrait/tall on mobile.
5. Collaboration OBS had no local mic input controls and participant positions were not predictable. User requested a center reference character that is rendered into the output like the grid.

## Preview changes
- Realtime subscription errors are no longer fatal to overlay boot. If the private channel fails or times out, the overlay continues with state/layout polling instead of aborting before microphone controls initialize.
- Added a lightweight `overlay_poll` Edge Function action that returns only participant state and room overrides. The client falls back to the existing `overlay_connect` snapshot action when the currently deployed Edge Function does not yet know `overlay_poll`; it applies only state/layout data and does not reload signed avatar image URLs on each polling tick.
- Polling cadence is 4 seconds when Realtime is unavailable and 10 seconds when Realtime is connected. Signed avatar assets are refreshed separately every 15 minutes.
- Added a manual overlay microphone control, microphone device selector, Grid toggle, Center Guide toggle, and hide/show controls. Microphone capture is started by a direct button gesture to accommodate Android WebViews that require user interaction before granting `getUserMedia`.
- Preserved the clean OBS link as the default. The link dialog now has a separate **Copy Link + Controls** action that adds `controls=1` for streaming apps where the user needs to tap the mic permission button. This avoids forcing buttons into every clean OBS Browser Source.
- Collaboration now uses one shared 1920×1080 stage. Each participant renderer uses the full landscape stage coordinate system rather than a narrow portrait slot. Default horizontal positions are deterministic; saved X/Y overrides remain in stage coordinates.
- Added a translucent vector mannequin / crosshair labeled CENTER GUIDE. It is drawn behind participant avatars in both Creator preview and OBS output, so it acts as a positioning reference instead of covering the avatar.
- Increased 3×3 grid line thickness and opacity substantially.
- Added a Creator-side room override checkbox to show/hide the center guide; the overlay control panel can also toggle it locally.
- Reduced microphone detection latency: analyser window 2048 → 1024 samples, level smoothing now reacts faster, state transition debounce 45 → 25 ms, and talking hangover 190 → 140 ms. Noise-floor adaptation and threshold gating remain enabled.
- Collaboration preview CSS now forces a responsive 16:9 canvas, while OBS overlay canvas sizing follows the intrinsic dimensions selected by room purpose.

## Important source/backend boundary
- Frontend and Edge Function source changes are committed in the Preview repository.
- The live Supabase Edge Function has NOT been deployed from this checkpoint. The client includes backward compatibility with the existing `overlay_connect` action for polling, but persistence of the new `showCenterGuide` override and the optimized `overlay_poll` action requires the Edge Function source to be deployed before those server-side additions are active.
- Supabase Live, Offline v1.7 RELEASE, and Online v1.0 remain otherwise untouched.
