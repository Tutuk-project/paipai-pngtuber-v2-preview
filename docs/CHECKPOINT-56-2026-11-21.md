## Step 1 implementation

1. Added shared `compareRoomMembers` / `sortRoomMembers` helpers in `src/avatar-renderer.js`.
2. Added `resolveRoomAvatarLayouts`, used by Creator and Collaboration OBS, to resolve transforms from the same sorted database-membership snapshot through `sortRoomMembers` and `resolveRoomAvatarPreferences`.
3. Added `resolveRoomBackgroundPreferences`. Creator and OBS now use the same room-background renderer path. Only the host's background is selected; every participant sprite profile is transparent.
4. Both `room_members` and `overlay_connect` continue to sign private background media on the server before the client renderer receives it.
5. Client layout writes now use an owner-only merge helper. Realtime `player-layout` broadcasts are invalidation signals only; Creator and OBS refresh the authorized database snapshot instead of applying untrusted `payload.overrides` to a member model.
6. The `set_room_override` Edge Function rejects a client-supplied mismatched `user_id`, verifies the authenticated user's room membership, and writes only with `user.id`.
7. Added migration `011_room_override_owner_rls.sql` and applied it to Development only. RLS `USING` and `WITH CHECK` both bind writes to `vio_private.vio_current_app_user_id()` and `vio_private.vio_is_room_member(room_id)`. The live project was not modified.
8. Default X rank is based on members in the database room-membership snapshot, not online presence. Presence loss/reconnect only changes visible state; it does not change membership order or resolved X. Added behavior tests for 1–4 members and for presence loss/reconnect.
9. Added tests for host-only private background selection, transparent participant sprites, signed snapshot paths, owner-only layout changes, and consistent avatar-renderer module identity within each page.

Explicit per-member X/Y/scale overrides remain authoritative. Persistent slot rank is still outside this step.

The original six distinct failing tests were classified as follows. Preview validation contained four of these same failures, so the original workflow totals were six and four, not ten distinct defects.

- `collaboration and OBS snapshots pass profile preferences and active-character assets to the shared renderer` — **(a) pure refactor/rename**. Replaced call-format matching with snapshot and shared-resolver contract coverage; signed assets and accessories remain covered.
- `room layout sliders update the local member renderer immediately` — **(b) protects an invariant**. Preserved owner-only optimistic updates, authenticated server ownership, and RLS. Realtime payloads can no longer mutate another member's model.
- `mobile navigation does not replace avatar, audio, OBS, backend, or Collaboration engines` — **(a) pure refactor/rename**. Replaced the old import-shape assertion with a module-identity contract: every `avatar-renderer.js` import within a page must use the same `?v` value. No cache-bust value is hard-coded in tests.
- `Collaboration Creator and OBS use one canonical room-layout transform` — **(b) protects an invariant**. Both paths use the shared layout resolver. Tests assert resolved outputs for one, two, three, and four database members rather than function-call syntax.
- `modular avatar renderer is wired into editor and OBS overlay` — **(a) pure refactor/rename**. Replaced import formatting checks with per-page module identity and renderer feature contracts.
- `private background media upload is owner-scoped and signed for editor, collaboration and OBS` — **(b) protects an invariant**. Tests cover server signing for both Creator and overlay snapshots, host-only background resolution, and transparent joiner sprites.

### Additional real regression found during triage

**(c) real regression:** the previous Realtime layout event handlers directly merged broadcast-supplied `payload.overrides` into whichever member row matched `payload.user_id`. A room participant could therefore spoof another member's identity in a broadcast and alter that member's in-memory layout model.

**Fix:** both Creator and overlay now treat layout broadcasts only as snapshot invalidations and reload the server-authorized database state. The server also rejects mismatched client-supplied `user_id` values, and migration 011 restores owner-scoped RLS for direct database writes.

### Additional refactor-only assertions corrected

During the repair, tests for the shared 1920×1080 stage, OBS renderer setup, and Pages artifact naming were updated to the new behavior/validated-commit contract. The signed-background assertion was updated for the Edge Function's typed `SupabaseClient` parameter. These were assertion mismatches, not product regressions. No test was disabled, deleted, or weakened.
