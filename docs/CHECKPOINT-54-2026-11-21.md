## Code findings from current main

1. Edge Function `overlay_connect` creates Supabase Storage signed URLs for expression assets and accessories with `createSignedUrl(..., 3600)` (one-hour TTL).
2. Overlay schedules `refreshMembers()` every 15 minutes, which should refresh signed asset URLs under normal operation. Actual timer execution and refresh errors are not yet evidenced.
3. `AvatarRenderer.image()` stores image elements in a per-renderer Map keyed by the full URL. It records failed loads as `null`; there was no explicit retry or visible failure diagnostic before this checkpoint.
4. Overlay render list is `members.slice(0, 4)`. The renderer map itself is keyed by `member.user_id`, but default horizontal layout in `resolveRoomAvatarPreferences()` depends on `memberIndex` and `memberCount`. Therefore slot/default positioning can change when list order or membership changes; stable member identity alone does not currently guarantee a stable default slot.
5. Broadcast layout events carry a page-local `seq` and overrides but no DB-backed version. Poll snapshots carry the override row's `updated_at`. The poll application path does not compare a snapshot's version against the most recently applied broadcast. A poll request started before a write/broadcast can therefore plausibly complete later and apply an older override. This is a concrete code-level race candidate; runtime HUD confirmation is still required.
6. Current `overlay_poll` returns member state and override fields, not avatar asset URLs. Asset URLs are refreshed by `overlay_connect` through `refreshMembers()`.
7. No changes have yet been made to version ordering, signed-URL retry/refresh semantics, member pruning, slot assignment, or regression tests. These require careful implementation and tests after the new HUD captures the failure boundary.
