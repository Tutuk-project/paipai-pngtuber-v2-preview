## User-reported findings and supplied recordings
Two portrait mobile recordings were reviewed:
- `1000004982.mp4` (approximately 3.76 seconds): Collaboration room stage and controls.
- `1000004983.mp4` (approximately 6.59 seconds): 16:9 stage with grid/center reference and X/Y/scale sliders being adjusted.

Reported symptoms:
1. Profile background appears to blink when microphone state/expression changes and when avatar position is dragged.
2. Collaboration OBS output remains centered instead of following the participant's Personal Controls.

The recordings show the Creator controls and stage. They do not include a direct capture of the OBS Browser Source output, so they establish the reported symptom context, not visual proof of the OBS-side result.

## Source-level root causes confirmed
1. `renderRoomParticipants()` cleared the visible Creator stage immediately on each render call, while the completed composite was drawn by a separate animation-frame callback. Mic-state and slider events could expose a blank intermediate frame.
2. Creator preview reapplied the complete saved profile and background-media configuration on every room render, then explicitly set the background image/video a second time. Position or microphone-state changes should not reconfigure profile background media.
3. Creator and OBS duplicated the X/Y-to-canvas transform in separate modules. The existing test verified similar formula text, not that both paths use the same transform implementation.
4. The OBS renderer only refreshed transforms at selected call sites, while the current polling interval was 10 seconds when Realtime was reported connected. A missed event could leave the OBS source stale.
5. Both page entry points used fixed asset query versions that could keep an older JS module in browser/WebView caches.
6. Layout persistence was primarily tied to the range `change` event. The new flow also schedules a debounced save during dragging and flushes on pointer, touch and keyboard release.

## Changes in this checkpoint
- Added `resolveRoomAvatarPreferences()` in `src/avatar-renderer.js` as the single canonical room transform used by Creator and OBS.
- Added `AvatarRenderer.setRoomLayout()`, which changes scale/X/Y without touching the background, decoded profile images, accessories or effect configuration.
- Creator and OBS now track profile/assets/accessory signatures and reapply those resources only when the underlying data changes.
- Creator preview no longer clears a populated visible stage before the next composite frame. It clears only when the room has no visible participants.
- Removed duplicate explicit background image/video assignment from the Creator Collaboration render path.
- OBS render now reapplies the current participant transform from the latest member model on each render path; Realtime and polling handlers update that model and then converge through render.
- Persist scale/X/Y while dragging (debounced), and flush the final position on `change`, `pointerup`, `touchend` and keyboard release paths. Successful save also broadcasts the persisted layout.
- Reduced Realtime-connected OBS reconciliation from 10 seconds to 2.5 seconds; disconnected fallback remains 1 second.
- Added focused regression tests for transform arithmetic, shared Creator/OBS helper usage, background preservation, no premature Creator canvas clear, OBS reconciliation and touch persistence.
- Bumped Creator, OBS and shared renderer module query versions to force the latest source to load.

## Device verification sequence
1. Hard-refresh the Creator page and open the same active Collaboration room.
2. Generate one Collaboration OBS link and keep that Browser Source open.
3. Drag Horizontal position from 0 to +30, then to -30. Do not regenerate the URL. Confirm OBS follows without requiring another link.
4. Drag Vertical position from 0 to -20 and then +20. Confirm Creator and OBS agree.
5. Change scale and then use Reset avatar layout. Confirm both preview and OBS update.
6. Repeat with two participants; test the four-participant room if available.
7. Use profile background image and video separately. Trigger Idle/Talking expression changes and drag X/Y/scale. Confirm background remains continuously visible without a flash.
8. Verify saved X/Y/scale still match after closing and reopening the room.
